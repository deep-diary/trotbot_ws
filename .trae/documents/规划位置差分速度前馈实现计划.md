# 实现计划：规划位置差分的 MIT 速度前馈（可开关 + 限幅 + 比例系数）

## 一、目标与范围

现状：CHAMP 只输出 12 关节角轨迹（`JointTrajectory.positions`），`motor_protocol_node` 把它映射成 MIT 帧，但 **`dq_des` 恒为 `default_velocity_`（配置里 0.0）**。k_fd 项实际是"零目标速度阻尼"。

本次实现：

1. 由**实际下发的平滑位置指令 `champ_smoothed`** 做时间差分，得到 `dq_ff`，填入 MIT 帧的 velocity 字段；
2. 总开关 `enable_velocity_ff`，默认 **关闭**（关闭时行为 100% 不变）；
3. 比例系数 `velocity_ff_scale`（整体缩放）+ 限幅 `velocity_ff_max_rad_s`（并可在线调节）；
4. 一阶低通 `velocity_ff_lpf_hz`，抑制差分噪声与步态相位切换处的速度跳变；
5. 把 `dq_ff` 填进已有 `/mit_motor_position_rad`（`JointState.velocity`），配套一个记录 + 绘图脚本，先验证"规划位置是否真连续"，再决定是否默认开启；
6. 运行期可通过 `/mit_gains_cmd` 与 `ros2 param set` 在线开关、调 scale/限幅。

不做：不引入规划器内部解析速度、不改 `kp/kd`、不改步态、不做加速度前馈。

## 三、代码改动

### 3.1 `config/control_gains.yaml` 新增参数

放在 `default_velocity: 0.0` 之后（L5 附近），保持中文注释风格：

```yaml
    # --- 规划位置差分速度前馈：v_ff = clamp(scale * d/dt(q_cmd), ±velocity_ff_max_rad_s) ---
    # 关闭时 velocity 字段仍用 default_velocity，行为与旧版完全一致
    enable_velocity_ff: false
    # 整体比例系数（1.0=直接用差分速度；0.7 更保守）
    velocity_ff_scale: 1.0
    # 电机侧绝对上限（rad/s，MIT 编码再受 ProtocolCodec::kVMax(50) 约束）
    velocity_ff_max_rad_s: 8.0
    # 一阶低通截止频率（Hz），<=0 关闭滤波；200Hz 指令下建议 15~25
    velocity_ff_lpf_hz: 20.0
    # 是否把 dq_ff 填进 /mit_motor_position_rad 的 velocity 字段（验证/绘图用）
    publish_velocity_ff: true
```

### 3.2 `src/motor_protocol_node.cpp`：核心实现

1. **参数声明**（L142 `default_velocity_` 之后）
   `enable_velocity_ff_`、`velocity_ff_scale_`、`velocity_ff_max_rad_s_`、`velocity_ff_lpf_hz_`、`publish_velocity_ff_`，默认值与 yaml 一致；构造末尾把 `last_commanded_mit_vel_rad_s_.fill(NaN)`、`has_vel_sample_.fill(false)`。

2. **新增成员**（L1320 之后的成员区）

```cpp
std::array<double, 12> last_vel_sample_champ_rad_{};
std::array<double, 12> last_vel_ff_rad_s_{};
std::array<double, 12> last_commanded_mit_vel_rad_s_{};
std::array<int64_t, 12> last_vel_sample_ns_{};
std::array<bool, 12> has_vel_sample_{};
double velocity_ff_max_clamp_{8.0};   // 运行时生效值
```

3. **新增 `ComputeVelocityFf(idx, champ_smoothed, now_ns)`**，紧跟 `SmoothJointCommand` 之后：

```
dt = (now_ns - last_vel_sample_ns_[idx]) * 1e-9
若 !enable_velocity_ff_ → ResetVelocityFf(idx); return 0
若 !has_vel_sample_[idx] || dt <= 1e-4 || dt > 0.1  → 更新采样点, return 0（首次/重启/丢帧不下发假速度）
raw = (champ_smoothed - last_vel_sample_champ_rad_[idx]) / dt        // CHAMP 域
filtered = velocity_ff_lpf_hz_ > 0 ? prev + dt/(tau+dt)*(raw-prev) : raw，tau = 1/(2π*fc)
更新采样点与 last_vel_ff_rad_s_[idx] = filtered
v_mit = joint_signs_[idx] * filtered * velocity_ff_scale_
return Clamp(v_mit, -lim, +lim)，lim = min(|velocity_ff_max_clamp_|, kVMax)
```

4. **`ResetVelocityFf(idx)` / `ResetAllVelocityFf()`**：清 `has_vel_sample_`、`last_vel_ff_rad_s_`、`last_commanded_mit_vel_rad_s_`（填 NaN）。重置点：
   - `ResetSmoothingForJoint()` 末尾（模式上升沿/锚点重置）；
   - `OnPowerGate()` 门禁关闭分支（L774-L777）。

5. **`SendMitFrame`**（L611-L635）

```cpp
const double v_ff = ComputeVelocityFf(idx, champ_smoothed, now_ns);
const double use_velocity = Clamp(default_velocity_ + v_ff,
                                  ProtocolCodec::kVMin, ProtocolCodec::kVMax);
// BuildMitControlFrame 的第 4 个参数改为 use_velocity
last_commanded_mit_vel_rad_s_[idx] = use_velocity;
```

把 velocity 一并带出（新增可选出参 `std::array<double,12>* velocity_out = nullptr`，与 `mapped_out` 同写法）。

6. **`OnTxRefreshTimer`**（L697-L704）：`use_velocity` 取 `last_commanded_mit_vel_rad_s_[idx]`（非有限值则回落 `default_velocity_`），避免补发帧把速度打成 0。

7. **`OnTrajectory`**（L531-L573）：新增 `mapped_vel`（NaN 填充）传给 `SendMitFrame`；当 `publish_mit_mapped_ && publish_velocity_ff_ && enable_velocity_ff_` 时把 `js.velocity` 设为 `mapped_vel`（保持 `js.name`/`position` 不变，velocity 为空即旧行为）。

8. **在线调参 / 参数回调**
   - `OnTuneCommand`（L1245-L1324）新增全局 token：`vff=0|1`（开关）、`vff_scale=<double>`（clamp 到 [0,3]）、`vff_max=<double>`（clamp 到 (0, kVMax]）；`reset=1` 时恢复参数值并 `ResetAllVelocityFf()`；日志行补 `vff=on/off,scale,max`。
   - `OnSetParameters`（L380-L512）新增对上述 5 个参数的处理，使 `ros2 param set /motor_protocol_node enable_velocity_ff true` 立即生效；开启时 `ResetAllVelocityFf()`。

9. **日志**：`MIT publish` 节流日志（L575-L578）补 `vff=%d scale=%.2f max=%.1f`；`LogTxWindowStats`（L717-L762）无需改。

10. **符号约定**：前馈只乘 `joint_signs_`，不乘 `tau_signs_`（后者仅力矩）。

## 四、假设与决策

| 决策 | 结论 |
|---|---|
| 差分对象 | 用**平滑后实际下发**的 `champ_smoothed`（不是原始 planner 输出），保证 v 与 p 严格一致；启动平滑窗口内 v 自然是平滑后的低速 |
| 是否叠加 `default_velocity` | 叠加（`default_velocity_ + v_ff`），默认 0 时等价于纯前馈 |
| 默认开关 | **关闭**；先按第五节验证，确认连续后再改 yaml 为 `true` |
| 速度域 | MIT 域（`sign*dq_champ`），与位置同域，绘图无需知道 signs |
| 限幅 | 双重：`velocity_ff_max_rad_s`（可调，默认 8）与 `kVMax=50`，取小 |
| 滤波 | 一阶 IIR，默认 20Hz；步态落足瞬间的速度跳变会被抹平约一个时间常数（8ms） |
| 补发帧 | 复用上一次实际下发的速度，避免周期性 0 |
| 绘图依赖 | numpy + 手写 SVG（matplotlib 在本机 ImportError） |

## 五、验证步骤

1. **编译**：`colcon build --packages-select trotbot_can_bridge`（如有 lint 报错先修正）。
2. **静态检查**：`ros2 param list | grep velocity`；`ros2 param get /motor_protocol_node enable_velocity_ff`（应为 false）。
3. **开启链路（先悬空/站立，不落地行走）**：
   - 正常 `can_bridge` + 上电门禁流程；
   - `ros2 param set /motor_protocol_node enable_velocity_ff true`；
   - `ros2 topic echo /mit_motor_position_rad --once` 确认 `velocity` 长度为 12 且数值合理（站立时应接近 0，肌电抖动 < 0.2 rad/s）。
4. **记录轨迹**：`ros2 run trotbot_can_bridge plot_velocity_ff.py --duration 10`（或直接 `python3 scripts/plot_velocity_ff.py`），期间用 teleop 慢速 trot 走 2~3 个步态周期。
5. **看图判定（验收标准）**：
   - `max|v_ff| ≤ velocity_ff_max_rad_s`，且削顶样本占比 < 1%（否则调高上限或降 scale）；
   - `v_ff` 与 `dq_numeric` 形态一致、无独立尖刺；若只在落足瞬间出现单点尖峰，属规划速度不连续，说明该场景不宜直接当前馈；
   - 若噪声大：调低 `velocity_ff_lpf_hz`（如 10Hz）或 `velocity_ff_scale`（如 0.7）。
6. **落地低速测试**：确认无啸叫/电流异常/温升异常后，再按需把 `control_gains.yaml` 的 `enable_velocity_ff` 改为 `true` 固化；若效果不佳则保持 false，参数与工具保留。
7. **回归**：`enable_velocity_ff: false` 时对比改动前后的 `MP TX window` 统计与 `/mit_motor_position_rad` 内容，确认与旧版一致（velocity 为空）。
