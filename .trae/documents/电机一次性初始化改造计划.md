# 电机一次性初始化改造计划（zero_sta ±180° + 上电免初始化）

## 1. 目标

1. 由手柄组合键 **Share + Options 长按 3 s** 触发一次「电机初始化」：把 EL05 的断电位置域参数 `zero_sta(0x7029)` 写为 `1` 并保存到电机 flash，使上电位置域从 `0~2π` 变为 `-π~π`（即 -180°~180°）。
2. 初始化只在维修/首次部署时执行一次；之后每次上电 **不再做 set_zero，也不再发 MIT `p=0` 首帧**，彻底消除「-1° 被解释成 359° → 回零转一圈暴动」。
3. 保留原有的手动机械零位（`set_zero`）能力，但必须与本次初始化互不误触。
4. 上电改为「使能即锚定当前反馈位置」：12 路反馈齐全才允许使能，首帧 MIT 用各电机当前角度而非 0。

## 2. 现状分析

### 2.1 当前上电流程（有问题的那条链路）

- 入口：`trotbot_basic.launch.py` → `can_bridge.launch.py` 同时拉起 `can_transport_node`、`motor_protocol_node`、`power_sequence_node`。
- 启动即发一次 0x7026 + 0x18 主动上报（`power_sequence_node.cpp:164-180`），不使能。
- 长按 start（L1+R1 或 □）后：`Precheck(0.2s)` → `EnableInit` → `DoEnableInitFrames()`（`power_sequence_node.cpp:555-578`）：
  1. 可选 `set_zero`（默认已关）
  2. 写 0x7026
  3. **CMD 0x03 使能**
  4. **MIT `p=0, kp=50, kd=2.5` 首帧**（`SendMitZeroAll`，`power_sequence_node.cpp:678-691`）
  5. 0x18 上报开
- 该 MIT `p=0` 帧绕过门禁与平滑，若某关节实际读数是 359°，就会以 50 的 kp 往 0 拉，即「旋转一圈暴动」。

### 2.2 现有可复用能力

- 帧编解码：`protocol_codec.hpp` 已有 MIT 编解码、`kPMin/kPMax=±12.57`、主动上报解析；**没有** 0x11/0x12/0x16 参数读写。
- 命令发送：`power_sequence_node` 已有 `BuildCmdFrame(cmd<<24 | master<<8 | motor_id)`、`SendCmdAll`、`SendEpScanTimeAll`、`SendSetZeroAll`。
- 反馈通道：`can_transport_node` 发布 `/can_rx_frames`（SensorDataQoS），`motor_protocol_node` 已订阅并解析 0x02/0x18。
- 启动平滑：`motor_protocol_node` 已有「首次反馈锚点 + 插值 + 速度限幅」（`SmoothJointCommand`，`motor_protocol_node.cpp:861-925`），并有使能上升沿重置锚点的能力（`ResetSmoothingForJoint`，`motor_protocol_node.cpp:819-830`，当前 `enable_mode_rising_smoothing: false`）。
- 脚本侧：`el05_motor_cansend.sh` 已有 `zero_sta_read/set/save/apply`，但 `cmd_zero_sta_save` 发的是全 0 数据（`:553-562`），而 a3 项目实测「全 0 save 不触发保存」，需修正为 `01 02 03 04 05 06 07 08`。

### 2.3 参考项目（a3_arm_ws）的关键结论

- `zero_sta=1` 是「断电位置域」参数，**只在下次上电重建多圈时生效**，写入后必须 `save_param(0x16)` 落 flash。
- 上电不 `set_zero`、不发 `p=0` 初值；使能后 `cmd_pos = hw_pos`（锚定当前反馈）。
- `save_param` 数据域必须是 `01..08`，全 0 不保存（LL-019）。
- 0x7005/0x7029 必须用 uint8 形式写（值放 `data[4]`），不能用 float 形式。

## 3. 方案总览

```
首次部署/维修：
  Idle + 门禁关 + 电机未使能
    └─ Share+Options 长按 3s
         ├─ 12 路 CMD 0x12：0x7029 = 1
         ├─ 12 路 CMD 0x16：data=01..08（保存 flash）
         ├─ 12 路 CMD 0x11：回读 0x7029
         └─ 结果事件：motor_init_ok / motor_init_fail（要求 12/12 == 1）
    └─ 断电重启（让 zero_sta 生效）

日常上电：
  launch → 0x18 上报打开（不使能、不写零）
  长按 start → Precheck
    → 校验 12/12 反馈新鲜（否则中止，不发使能）
    → CMD 0x03 使能
    → MIT 首帧 p = 各电机当前反馈角（不再 p=0）
    → 0x18 上报开
    → SoftStand → Running
```

## 4. 具体改动

### 4.1 `src/trotbot_can_bridge/include/trotbot_can_bridge/protocol_codec.hpp`

**为什么**：让 C++ 侧具备写/存/回读 `0x7029` 的能力，不再依赖 cansend 脚本抢总线。

**改什么**：

1. 在命令常量区（现第 18-21 行）补充：

```cpp
static constexpr uint8_t kMotorCmdGetParam  = 0x11;  // 读参数
static constexpr uint8_t kMotorCmdSetParam  = 0x12;  // 写参数
static constexpr uint8_t kMotorCmdSaveParam = 0x16;  // 参数存 flash
```

2. 补充参数常量（与 `kPMin` 同区）：

```cpp
static constexpr uint16_t kParamZeroSta = 0x7029;  // 0=上电域 0~2π，1=-π~π
```

3. 新增结构体与三个 builder + 一个 decoder（放在 `BuildMitControlFrame` 之后）：

```cpp
struct GetParamResponse {
  uint8_t motor_id{0};
  uint16_t param_id{0};
  uint8_t value_u8{0};
};

// 写参数（uint8 形式）：CMD 0x12，data[0..1]=param 小端，data[4]=value
static CanFrameMessage BuildSetParamU8Frame(CanBus bus, uint8_t motor_id, uint16_t param_id, uint8_t value);

// 保存参数：CMD 0x16，data = 01 02 03 04 05 06 07 08（全 0 不触发保存）
static CanFrameMessage BuildSaveParamFrame(CanBus bus, uint8_t motor_id);

// 读参数：CMD 0x11，data[0..1]=param 小端
static CanFrameMessage BuildGetParamFrame(CanBus bus, uint8_t motor_id, uint16_t param_id);

// 读参数应答：cmd_type 必须=0x11；应答帧低字节=主站(默认 0xFD)、次字节=电机 ID；
// data[0..1]=param 小端，data[4]=uint8 值
static std::optional<GetParamResponse> DecodeGetParamResponse(
  const CanFrameMessage & frame, uint8_t master_id = 253);
```

CAN ID 组装与现有 `power_sequence_node::BuildCmdFrame` 保持一致：
`cmd<<24 | master_id<<8 | motor_id`。

**注意**：`DecodeGetParamResponse` 必须过滤「请求回环」——请求帧低字节是 `motor_id`，应答帧低字节是 `master_id`，按低字节匹配主站即可。

#### 4.2.2 新增订阅

增加 `/can_rx_frames`（`std_msgs/UInt8MultiArray`，`rclcpp::SensorDataQoS()`）订阅，回调 `OnCanRxFrame`：

```cpp
void OnCanRxFrame(const UInt8MultiArray::SharedPtr msg) {
  const auto frame = FrameCodec::Unpack(*msg);
  if (!frame) return;

  // 1) 缓存电机反馈角（MIT 域 rad），供「上电保持帧」和新鲜度校验
  if (auto fb = ProtocolCodec::DecodeFeedback(*frame)) {
    last_feedback_angle_rad_[fb->motor_id] = fb->current_angle;
    last_feedback_stamp_ns_[fb->motor_id] = now().nanoseconds();
  }

  // 2) 初始化回读阶段收集 0x7029 应答
  if (motor_init_active_ && motor_init_phase_ == MotorInitPhase::ReadBack) {
    if (auto rsp = ProtocolCodec::DecodeGetParamResponse(*frame, motor_master_id_)) {
      if (rsp->param_id == ProtocolCodec::kParamZeroSta) {
        motor_init_readback_[rsp->motor_id] = rsp->value_u8;
        motor_init_has_readback_[rsp->motor_id] = true;
      }
    }
  }
}
```

成员数组按电机 ID 索引（ID ≤ 63）：

```cpp
std::array<double, 64> last_feedback_angle_rad_{};
std::array<int64_t, 64> last_feedback_stamp_ns_{};   // 0 = 未收到
std::array<int, 64> motor_init_readback_{};          // -1 = 未收到
std::array<bool, 64> motor_init_has_readback_{};
```

#### 4.2.3 一次性初始化状态机（非阻塞）

新增独立 wall timer（周期 `motor_init_tick_ms`，常驻），回调 `TickMotorInit()`。
**不要**在回调里 sleep，避免阻塞 `/joy` 与 CAN 接收（回读需要同一执行器继续收帧）。

```cpp
enum class MotorInitPhase { Idle, SetZeroSta, SaveParams, ReadBack };
```

`BeginMotorInit(trigger, verify_only)` 前置条件：

- `!motor_init_active_`
- `state_ == SequenceState::Idle && !gate_open_`
- 非 verify_only 时要求 `enable_remote_motor_init_ == true`
- 失败则发布 `motor_init_rejected:<state>:gate=<0|1>:<trigger>` 并 WARN

执行顺序：

1. **SetZeroSta**：12 路 `BuildSetParamU8Frame(bus, id, kParamZeroSta, target)`，等待 `motor_init_set_wait_ms`
2. **SaveParams**：12 路 `BuildSaveParamFrame(bus, id)`，等待 `motor_init_save_wait_ms`
3. **ReadBack**：12 路 `BuildGetParamFrame(bus, id, kParamZeroSta)`，等待 `motor_init_read_wait_ms` 收集应答
4. **结算**：
   - 12/12 都有回读且 `value_u8 == target` → `motor_init_ok:zero_sta=1:12/12`，日志 WARN 提示「需断电重启后生效」
   - 否则 → `motor_init_fail:zero_sta=1:ok=N/12:missing=id,id...`，日志 ERROR
   - 无论成败，`motor_init_active_=false`、phase 回 `Idle`

`verify_only=true`（上电自检）直接从 ReadBack 开始，只读不写：结果 `zero_sta_verify_ok` / `zero_sta_verify_fail`（后者 WARN「未完成一次性初始化，请 Share+Options 长按 3s」）。

初始化期间（`motor_init_active_`）：

- 在 `OnTimer()` 顶部先 `TickMotorInit()`；
- 若 active 则直接 return，**不再处理 start/shutdown/prone**，防止初始化途中开门禁或运动；
- `OnCommand` 收到 `start/prone/shutdown` 时也直接 WARN 拒绝。

## 5. 假设与已定决策

| 项 | 决策 |
|---|---|
| 触发方式 | `Share + Options` 同时长按 3 s（复用 `button_share=8`、`button_option=9`） |
| 初始化内容 | 只写 `zero_sta=1` → 保存 → 回读校验；**不改机械零位** |
| 机械零位 | 保留 Options 单键 / 话题 `set_zero`，但与初始化互斥 |
| 上电行为 | 不 set_zero、不发 p=0；12/12 反馈新鲜 → 使能 → 按当前角保持 |
| 持久化 | 依赖电机自身 flash；不新增 ROS 侧标记文件 |
| `zero_sta` 生效时机 | 仅下次上电；日志与事件中明确提示 |
| 反馈不可用 | 中止 start，不发任何使能帧（不做 p=0 兜底） |
| 角度域兼容性 | 现有 `joint_offsets_rad` 无需改：站立/趴姿下 12 路电机域角均在 ±π 内（站立实测 hip≈0、thigh≈±0.425、calf≈±1.496） |

### 6.2 台架/实机验证（按顺序）

1. **上电只读自检**
   - 启动 `trotbot_basic.launch.py`，不按 start。
   - 观察日志：`zero_sta_verify_ok:1` 或 `zero_sta_verify_fail`（12 路回读结果与缺失 ID）。
2. **组合键初始化**
   - Idle、未站起时按住 Share+Options 3 s。
   - 日志应依次出现 `SetZeroSta → SaveParams → ReadBack`，最终 `motor_init_ok:zero_sta=1:12/12`。
   - `candump` 抽查：`0x12xxFDxx`（0x7029=1）、`0x16xxFDxx`（data=01..08）、`0x11xxFDxx`。
3. **持久化验证**
   - 断电 >10 s 后重新上电，再跑一次只读自检，应为 `zero_sta_verify_ok:1`。
   - 或 `ZERO_STA_TARGET=1 bash el05_motor_cansend.sh zero_sta_read`（注意：先停掉 ROS 节点，避免抢总线）。
4. **断电小角度扰动复测（ISSUE-0003 原始场景）**
   - 趴姿断电，人工把某关节正向/负向各拨 ~10°，上电后看 `/joint_states_feedback`：读数应连续（≈±0.17 rad），不应出现 ≈6.1 rad。
5. **免初始化站立**
   - 长按 start：日志无 `set_zero`、无 `p=0`；`/motor_feedback` 中 `cmd_angle` 应与 `angle` 接近（差值接近 0）。
   - 狗子不应出现整圈旋转或瞬时站立脉冲。
6. **失效保护**
   - 拔掉 1 个电机后 start：应出现 `abort start: feedback 11/12 fresh`，且 `candump` 中**没有**任何 CMD 0x03 使能帧；状态回到 Idle。
7. **话题入口**
   - `ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'motor_init'}"` 与按键等价。
   - 非 Idle 或门禁开时，应返回 `motor_init_rejected` 且不写参数。
8. **互斥验证**
   - 初始化进行中按 L1+R1 不应进入 precheck；Options 单键（不按 Share）仍只触发 `set_zero`。

## 7. 风险与回滚

| 风险 | 处理 |
|---|---|
| 某路电机不回 0x11 应答（老固件） | 回读判失败但参数已写入/保存；事件中列出缺失 ID，可用脚本复查；不阻断后续上电 |
| `require_feedback_before_enable=true` 与关闭主动上报冲突 | 文档明确要求 `enable_active_report_at_launch/enable_active_report_in_startup` 为 true；否则 start 会中止 |
