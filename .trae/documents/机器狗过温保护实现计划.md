# 机器狗过温保护（等效 R3 下电）实现计划

## 一、需求与结论

**需求**：任意电机温度达到 100°C 时，自动执行与「按下 R3」完全一致的动作——退出当前模式 → 软趴 safe-park → 失能 → 回到 `Idle` 休息降温。

**现状结论：狗子目前不具备该功能。**

- 温度数据已经存在：`/can_rx_frames` 里 `0x18`（主动上报）/`0x02`（应答反馈）帧的 `data[6..7]` 已被解析为 `MotorFeedback::current_temp`（单位 °C，分辨率 0.1，大端）。
- 但温度只被用于：`/motor_feedback` 字符串打印、`/diagnostics` 的 `temp_c` 字段；**不参与任何动作决策**。
- 固件 `temp_error` 故障位（CAN ID bit18）只被塞进诊断 `fault_mask` 的 bit3，进而只影响手柄红灯/震动，**不会停车或失能**。
- `SequenceState::Fault` 是空壳（无任何 `EnterState(Fault)`、无出口逻辑），不可直接复用。
- 全仓无 `thermal` / `overheat` / `max_temp` 之类阈值保护；`README.md:566` 的 `safety_manager_node` 仍是 Backlog。

**已确认的设计选择（用户选择）**

1. **锁定 + 滞回**：触发后屏蔽 L3 上电，直到所有有效电机温度降到恢复阈值（默认 80°C）以下，且仍需人工按 L3 才会上电。
2. **仅日志**：触发/解除只打 `RCLCPP_ERROR`/`WARN` 日志，不新增话题、不改状态机、不接灯。

## 三、改动方案

### 3.1 `src/trotbot_can_bridge/config/power_sequence.yaml`

在「反馈新鲜度」块之后（现 L88 之后）追加，并保持现有中文注释风格：

```yaml

    # 任一路有效反馈温度 >= thermal_limit_c 并持续 thermal_debounce_s 后触发一次；
    # 触发后锁存，屏蔽 L3/start 上电，直到所有有效温度 <= thermal_recover_c 才解锁（仍需人工按 L3）。

    # 超过该秒数没有 0x18/0x02 反馈的电机视为无效，不参与判定

```

**(d) 新增两个私有方法**（建议放在 `BeginSoftProne` 之前，L504 附近）

```cpp
/// 扫描缓存，返回最高有效温度；无有效数据返回 -1.0
double MaxFreshMotorTempC(int * motor_id_out)
{
  double max_temp = -1.0;
  int max_id = -1;
  const int64_t now_ns = this->now().nanoseconds();
  for (size_t id = 0; id < last_feedback_temp_c_.size(); ++id) {
    if (last_feedback_stamp_ns_[id] <= 0) {
      continue;
    }
    const double age_s = static_cast<double>(now_ns - last_feedback_stamp_ns_[id]) / 1e9;
    if (age_s > thermal_fresh_timeout_s_) {
      continue;
    }
    if (last_feedback_temp_c_[id] > max_temp) {
      max_temp = last_feedback_temp_c_[id];
      max_id = static_cast<int>(id);
    }
  }
  if (motor_id_out) {
    *motor_id_out = max_id;
  }
  return max_temp;
}

/// 过温判定 + 锁存/滞回。返回 true 表示本 tick 已触发（调用方应立即 return）
bool UpdateThermalProtection(double dt)
{
  if (!enable_thermal_protection_) {
    return false;
  }
  int max_id = -1;
  const double max_temp = MaxFreshMotorTempC(&max_id);

  if (thermal_latched_) {
    // 所有有效温度都回落到恢复阈值以下才解锁；无有效数据时保持锁存（保守）
    if (max_temp >= 0.0 && max_temp <= thermal_recover_c_) {
      thermal_latched_ = false;
      thermal_over_s_ = 0.0;
      RCLCPP_WARN(
        this->get_logger(),
        "thermal protection cleared: max temp %.1f C <= %.1f C; press L3 to power on again",
        max_temp, thermal_recover_c_);
    }
    return false;
  }

  if (max_temp >= thermal_limit_c_) {
    thermal_over_s_ += dt;
    if (thermal_over_s_ < thermal_debounce_s_) {
      return false;
    }
    thermal_latched_ = true;
    thermal_hot_motor_id_ = max_id;
    thermal_hot_temp_c_ = max_temp;
    RCLCPP_ERROR(
      this->get_logger(),
      "thermal protection TRIGGERED: motor=%d temp=%.1f C >= %.1f C; "
      "perform R3-equivalent safe-park -> disable (state=%s)",
      max_id, max_temp, thermal_limit_c_, StateName(state_));
    TriggerThermalShutdown();
    return true;
  }

  thermal_over_s_ = 0.0;
  return false;
}

/// 与 R3 完全等价的下电路径复用
void TriggerThermalShutdown()
{
  switch (state_) {
    case SequenceState::Running:
    case SequenceState::Precheck:
    case SequenceState::EnableInit:
    case SequenceState::SoftStand:
      BeginSoftProne(true);
      break;
    case SequenceState::SoftProne:
      // 已在趴下途中：不重新锚定 z0（避免高度跳变），仅升级为「趴完再失能」
      pending_start_after_prone_ = false;
      use_stand_resume_for_softstand_ = false;
      soft_prone_then_disable_ = true;
      break;
    case SequenceState::ProneHold:
      EnterState(SequenceState::Disable);
      break;
    case SequenceState::Idle:
    case SequenceState::Disable:
    case SequenceState::Fault:
    default:
      break;
  }
}
```

**(e) `OnTimer` 挂载（L375-377 的 `motor_init_active_` 早退之后、L379 `Idle` 分支之前）**

```cpp
    // 过温保护：等效 R3，最高优先级；触发当 tick 直接接管
    if (UpdateThermalProtection(dt)) {
      return;
    }
```

放在 `motor_init_active_` 之后的原因：设零期间电机未使能、门禁关闭，不应被热保护打断；且此时 `state_` 为 `Idle`，`TriggerThermalShutdown()` 本身也是 no-op。

**(f) 锁存期间屏蔽上电（3 处）**

1. `OnTimer` `Idle` 分支（L381）：

```cpp
      if (l3_edge) {
        if (thermal_latched_) {
          RCLCPP_WARN(
            this->get_logger(),
            "joy L3 ignored: thermal protection latched (motor=%d was %.1f C, need <= %.1f C)",
            thermal_hot_motor_id_, thermal_hot_temp_c_, thermal_recover_c_);
          return;
        }
        ... 原逻辑
      }
```

2. `OnTimer` `ProneHold` 分支的 `square_edge`（站起也是使能态延续）：同样先判 `thermal_latched_`，命中则 `WARN` 并忽略。

3. `OnCommand` 的 `start` 分支入口（L280 之后）：`if (thermal_latched_) { WARN; return; }`。

`R3`/`shutdown`/`prone`/`set_zero` 不受锁存影响（继续允许下电）。

## 四、行为定义（决策完备）

| 触发时状态 | 动作 |
|---|---|
| `Running` / `Precheck` / `EnableInit` / `SoftStand` | `BeginSoftProne(true)` → 软趴 2.5s → `Disable` 失能 → 0.25s → `Idle` |
| `SoftProne`（○ 趴下途中） | 升级为「趴完即失能」，不重锚 `z0` |
| `ProneHold` | 直接 `EnterState(Disable)` |
| `Idle` / `Disable` / `Fault` | 只记录日志并锁存，无额外动作（已失能） |

- **去抖**：连续 `>= thermal_limit_c` 累计 `thermal_debounce_s`（默认 0.5s ≈ 25 个 tick）才触发，避免单帧毛刺。
- **新鲜度**：只用 `<= thermal_fresh_timeout_s`（默认 2s）内的反馈；全部超时则视为无数据，不触发也不解锁。
- **锁存与解锁**：触发即锁存；当**有有效数据且最大值 `<= thermal_recover_c`** 时自动解锁并打 WARN；解锁后仍需人工按 L3。
- **进程重启**：锁存为内存态，重启节点/断电后清零（符合「休息降温后再上电」的直觉）。

## 五、假设与非目标

- 假设温度字段可信（`protocol_codec.hpp:160` 已验证 0.1°C、大端）。
- 不新增 `Fault` 状态、不改状态灯 `status_led_map.yaml`、不改 `ds4_feedback_node`。
- 不新增话题；不处理固件 `temp_error` 位（该位仍只走原诊断/红灯链路）。
- 不改 `motor_protocol_node`、不改 `motor_monitor_node`。
- 阈值仅对反馈温度生效，不做电流/力矩热模型估算。
