# 遥控与电源启停（power_sequence / champ_teleop）

本文承接根目录 `README.md`，涵盖：`power_sequence_node` 话题指令与状态语义、手柄按键、键盘与 PS4 遥控、行走 / 姿态轴映射。

## 1) `power_sequence`：话题手动触发（无手柄 / 桌面调试）

当 `can_bridge.launch.py` 默认拉起 **`power_sequence_node`**（或整机 `use_can_bridge:=true`）时，除手柄组合键外，可直接向 **`/power_sequence/command`** 发 **`std_msgs/msg/String`**，用于上电流程、趴下、下电（与 `power_sequence_node` 内建指令一致，大小写不敏感）：

```bash
# 上电 / 启动流程（Idle 等允许状态下才会进入；否则节点会打 ignore 日志）
ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'start'}"

# 趴下（在允许状态下触发）
ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'prone'}"

# 下电流程
ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'shutdown'}"

# 十二电机机械零位（仅 Idle + gate 关闭时生效；无手柄调试用）
ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'set_zero'}"

# 一次性电机初始化：写 zero_sta(0x7029)=1 并保存到电机 flash（仅 Idle + gate 关闭；写后需断电重启生效）
ros2 topic pub --once /power_sequence/command std_msgs/msg/String "{data: 'motor_init'}"
```

执行前请 **`source install/setup.bash`**，且 **`power_sequence_node` 已在运行**。观察状态可配合：

```bash
ros2 topic echo /power_sequence/state --once
ros2 topic echo /power_sequence/gate_open --once
```

说明：若当前状态机不允许该指令，节点会忽略并输出 `ignore command=...`；未知字符串会提示 `supported: start/prone/shutdown/set_zero/motor_init`。

### 指令语义（与 `power_sequence_node` 一致）

| 指令 | 作用概要 |
|------|----------|
| `start` | `Idle` → 上电站立流程；**`ProneHold`（已趴下且仍使能）** → 再次进入 `SoftStand` 站起 |
| `prone` | 仅在 **`Running`**：`SoftProne` 过渡到趴姿目标后进入 **`ProneHold`**，**不发 Reset、保持使能与 gate** |
| `shutdown` | **`ProneHold`**：直接进入 **`Disable`**（全机 `Reset` 后回 `Idle`）；其余 **`Idle` / `Precheck` / `EnableInit` / `SoftStand` / `Running` / `SoftProne`**：先 **`SoftProne`**，再 **`Disable`** |
| `set_zero` | **维修后机械零位**：仅 **`Idle`** 且 **`gate_open=false`** 时对 12 电机发 EL05 **`set_zero`**（CMD 0x06）；非 Idle 拒绝（日志 WARN）。与 URDF `joint_offsets` 标定不同层 |
| `motor_init` | **一次性电机标定初始化**：仅 **`Idle`** 且 **`gate_open=false`** 时执行 `set_zero`（当前姿态=机械零位）→ 写 `zero_sta(0x7029)=1` → CMD 0x16 保存 flash → CMD 0x11 回读校验（要求 12/12）。**必须在零位工装姿态下操作**；**写后需断电重启生效** |

手柄等效（短按 = 按下沿）：**`L3`** 短按 → **`start`** 上电/使能（唯一上电入口）；**`□`（Square）** 短按 → **stand** 站起（仅 `ProneHold` → `SoftStand`）；**`○`（Circle）** 短按 → **idle** 趴下（仅 `Running` → `SoftProne` → `ProneHold`，保持使能）；**`R3`** 短按 → 下电 `shutdown`（回 idle `SoftProne` 后 `Disable`；唯一下电入口，Running/ProneHold/启动过程均生效）；**`L1+R1`** 长按（未上电 `Idle`、门禁关）→ **`motor_init`**。PS4 布局默认 `button_l3:=11`、`button_r3:=12`、`button_square:=3`、`button_circle:=1`，若与 `sensor_msgs/Joy` 不符请改 `power_sequence.yaml`。

**机械零位（RQ-024）**：唯一手柄入口是**未上电（`Idle` + 门禁关）时 `L1+R1` 长按** → **`motor_init`**（`set_zero` + `zero_sta=1` 即 -180°~180° + 保存 + 回读），**必须在零位工装姿态下操作**，**写后需断电重启生效**；`Options` / `Share+Options` 手柄入口已取消。无手柄时可用话题 **`set_zero`** / **`motor_init`**。勿与 **`el05_motor_explicit_cmds_12_direct.sh`** 等 **cansend** 脚本并发抢总线。

**`Running` 时再触发 `start`（话题或 L3）**：话题会 **`ignore`**；手柄在 **`Running`** 分支**只处理** `idle` 趴下与 `R3` 下电，**不会**执行 start，也**不会**先趴再起。

**关于 `SoftProne` / `SoftStand` 的高度**：默认 **`track_body_pose_height:=true`** 时，进入 **`SoftProne`（含下电路径）** 会以**最近一次有效的 `body_pose.position.z`（与本节点发布同源话题）** 为起点插值到 `prone_z`，避免遥控压低高度后仍先抬回 `stand_z` 再趴。仅 **`prone` 路径**在趴下前会记录 **`stand_resume_z`**，随后话题 **`start` 站起** 时 `SoftStand` 插值到该高度而非固定 `stand_z`，减轻「站回名义高度再突然下落」的跳变。**`□` 短按站起**固定用 **`stand_z`**（名义站姿）；冷启动 **`Idle`→`L3`** 也用 `stand_z`。跟踪超时（`body_pose_stale_s`）或无样本时回退到本节点**上次发布的 z**，再回退 `stand_z`。参数见 `power_sequence.yaml`。

**`ProneHold` 与 `start`（站起）**：`ProneHold` 持续发布 **`prone_z`**（相对 CHAMP 名义高度的 z 增量，**不是**机械结构上的「全局最低点」）。从 **`ProneHold` 发 `start`** 只会进入 **`SoftStand`**：在 **`stand_z`↔`prone_z`** 上从趴姿插值回站姿，**不会**先发失能、也不会再走一遍 `EnableInit` 的使能/MIT 保持帧（电机已在运行态）。若在 **`SoftProne`（趴下动画）尚未结束**时发 `start`，实现上会 **挂起**：动画结束后直接进入 **`SoftStand`**，避免第一次 `start` 被忽略、需连发两次的现象。

**关于 `ros2 topic pub ... Waiting for at least 1 matching subscription(s)...`**：这是 **ROS 2 CLI 在等 DDS 发现订阅者**（`power_sequence_node` 未起来或 discovery 慢），与机体是否站立**无因果关系**；有/无这行日志都不应作为「站得好不好」的判断依据。

## 2) 遥控：键盘 / PS4 手柄（可选）

本节对应 **单独再开一个终端** 拉的 `champ_teleop`（与 **`trotbot_basic` 整机栈**分开启动）。使用前请先 **`source install/setup.bash`**。

### 2.1 键盘（默认同时启用手柄；纯键盘需关闭 `use_joystick`）

默认会启动 **`joy_node` + 手柄灯条/振动反馈**，并在 **`xterm`** 里打开键盘遥控窗口（需本机有图形桌面与 `DISPLAY`）。只有键盘时显式关闭手柄：

```bash
ros2 launch trotbot trotbot_teleop.launch.py use_joystick:=false
```

无桌面 / SSH 无 X11 时，在同一 TTY 里跑键盘（**不用 xterm**）：

```bash
ros2 launch trotbot trotbot_teleop.launch.py use_joystick:=false use_xterm:=false
```

（需在**真实终端**里焦点在该窗口，否则读不到按键。）

### 2.2 PS4 手柄（示例：`/dev/input/js0`）

1. **确认设备节点**（你已连接 PS4 且为 `js0` 时可跳过改名）：

   ```bash
   ls -l /dev/input/js0
   ```

2. **权限**：确保当前用户在 **`input`** 组（否则 `joy_node` 打不开设备）：

   ```bash
   groups | grep input || sudo usermod -aG input "$USER"
   ```

   改组后需 **重新登录** 或 **`newgrp input`** 后再试。

3. **先开整机栈**（另一终端，含 `quadruped_controller` 等），再开遥控：

   ```bash
   ros2 launch trotbot trotbot_teleop.launch.py joystick_dev:=/dev/input/js0
   ```

   `use_joystick` 与 `joystick_dev` 默认分别为 **`true`** 与 **`/dev/input/js0`**，与你的设备一致时可直接：

   ```bash
   ros2 launch trotbot trotbot_teleop.launch.py
   ```

4. **可选自检**：确认 `/joy` 有数据：

   ```bash
   ros2 topic echo /joy --once
   ```

5. **手柄灯条 / 振动反馈**（默认开启）：`trotbot_teleop.launch.py` 会同时启动 `ds4_feedback_node`，按狗子电源状态改变 PS4 灯条颜色，并在就绪/下电/故障/起步时振动。

   ```bash
   # 默认即启用；关闭：追加 use_ps4_feedback:=false
   ros2 launch trotbot trotbot_teleop.launch.py
   # 无手柄/无权限时节点不退出，只发布调试 JSON
   ros2 topic echo /trotbot/ps4/feedback
   ```

   需要当前用户对 `/dev/hidraw*` 有读写权限（常见为 `dialout` 组）。灯色复用 `src/trotbot_status_led/config/status_led_map.yaml`，与 WS2812 灯带同语义，详见 [`src/trotbot_status_led/README.md`](../../src/trotbot_status_led/README.md)。

### 2.3 键盘和手柄是「二选一」吗？

**不是启动层面的二选一。** `use_joystick:=true` 时会同时：

- 启动 **`joy_node`**（读手柄，发布 **`/joy`**），以及  
- 启动 **`champ_teleop`**（键盘线程仍在「键盘所在终端 / xterm」里等待按键）。

二者都会向 **`cmd_vel`**、`body_pose` 等话题发指令（**谁后发谁覆盖**，没有 `twist_mux` 仲裁）。  
因此：**可以同时连着**，但若一手键盘一手柄同时推杆，运动会「抢话题」。常规用法是 **同一时间只用一种输入**，或只用键鼠停住再用手柄。

**若 `/joy` 有数据、RViz/真机却像不响应手柄**：旧版 `champ_teleop` 主线程一直卡在键盘读键、**没有 `spin`**，导致 **`joy_callback` 从不执行**；本工作空间内已改为 **后台 `SingleThreadedExecutor` 处理 `/joy`**。更新后请 **`colcon build --packages-select champ_teleop`** 并 **`source install/setup.bash`** 再启动。若仍无响应，再按下一节核对 PS4 轴/键编号是否与脚本一致。

### 2.4 电源 / 设零按键（`power_sequence_node`）

下表为 `src/trotbot_can_bridge/config/power_sequence.yaml` 默认值（PS4/CUH-ZCT2E 实测：`✕=0 ○=1 △=2 □=3 L1=4 R1=5 L3=11 R3=12`）。短按指**按下沿**，各键设 `-1` 可关闭。

| 物理键 | `buttons` 下标 | 生效状态 | 动作 |
|---|---|---|---|
| **L3 短按** | 11 | `Idle` | 上电/使能 `start` → `Precheck → EnableInit → SoftStand → Running`（**唯一上电入口**） |
| **□ 短按** | 3 | `ProneHold` | 站起 `SoftStand`（目标 `stand_z`） |
| **○ 短按** | 1 | `Running` | 趴下 `SoftProne → ProneHold`，**保持使能** |
| **R3 短按** | 12 | `Running` / `ProneHold` / 启动过程 | **唯一下电入口**：`Running`/启动过程先 `SoftProne` 再 `Disable`；`ProneHold` 直接 `Disable` |
| **L1+R1 长按 3s** | 4+5（且未按 Share） | `Idle` 且门禁关 | **唯一设零入口** `motor_init`：`set_zero` + `zero_sta=1`（-180°~180°）+ 保存 flash + 回读 12/12。**必须在零位工装姿态下操作，写后断电重启生效** |

- 其余状态按 R3、或 `Idle` 按 R3/□/○ 均忽略，避免误动作。
- 无手柄时等效话题：`/power_sequence/command`（`start` / `prone` / `shutdown` / `set_zero` / `motor_init`）。
- `champ_teleop` 自身不处理这些键；`Share`、`Options`、十字键当前未绑定。

#### 过温保护（等效 R3 下电）

`power_sequence_node` 直接消费 **`/can_rx_frames`** 中的 **`0x18`**（主动上报）/ **`0x02`**（应答反馈）温度（`data[6..7]`，大端，0.1 °C），不需要额外话题：

- **触发**：任一路**新鲜**（`thermal_fresh_timeout_s`，默认 2 s 内有反馈）温度 ≥ **`thermal_limit_c`**（默认 **100.0** °C）并持续 **`thermal_debounce_s`**（默认 **0.5** s）→ 执行与 **R3** 完全一致的路径：`Running` / 启动过程 / `SoftStand` → `SoftProne` → `Disable` → `Idle`；`ProneHold` → `Disable`；`SoftProne` 途中则升级为「趴完即失能」（不重新锚定 `z0`，避免高度跳变）。
- **锁存 + 滞回**：触发后屏蔽上电——`Idle` 按 `L3`、话题 `start`、`ProneHold` 按 `□` 均被忽略并打 `WARN`；当**所有有效温度** ≤ **`thermal_recover_c`**（默认 **80.0** °C）时自动解锁并打 `WARN`，之后仍需**人工按 `L3`** 上电。全部反馈超时视为无数据，只保持锁存、不解锁。
- **不受影响**：`R3` / `shutdown` / `prone` / `set_zero` 仍可正常触发（继续允许下电）。关闭该功能：`enable_thermal_protection: false`。
- **台架自测**（不接电机）：以 `-p thermal_limit_c:=35.0` 启动，另开终端注入一帧伪造上报（电机 51、100.0 °C = `0x03E8`）：

```bash
ros2 topic pub --once /can_rx_frames std_msgs/msg/UInt8MultiArray \
  "{data: [0, 1, 8, 24, 0, 51, 253, 0, 0, 0, 0, 0, 0, 3, 232]}"
```

预期日志：`thermal protection TRIGGERED: motor=51 temp=100.0 C ...`；再注入 20 °C（末两字节 `0, 200`）应出现 `thermal protection cleared`。

### 2.5 行走 / 姿态映射（`champ_teleop` 源码约定）

以下为 `champ_teleop` 里 **`joy_callback`** 使用的 **轴/键索引**。不同品牌（含 PS4）在 Linux 下 **`sensor_msgs/Joy` 下标可能不一致**，若方向或功能不对，用 **`ros2 topic echo /joy`** 对照后再改 `src/champ_teleop/champ_teleop.py` 或做一层 remap；PS4 细表见 [`src/champ_teleop/docs/PS4_JOY_MAPPING_zh.md`](../../src/champ_teleop/docs/PS4_JOY_MAPPING_zh.md)。

| 作用 | 索引 |
|------|------|
| 前后移动 `cmd_vel.linear.x` | `axes[1]`（左摇杆前后） |
| 左摇杆左右：按住 `buttons[4]`（L1）→ 横向平移 `linear.y`；不按 → 原地转向 `angular.z` | `axes[0]` |
| 右摇杆左右：按住 `buttons[5]`（R1）→ `yaw`；不按 → `roll` | `axes[3]` |
| 右摇杆前后 → `pitch` | `axes[4]` |
| 升高 / 降低 `body_pose.position.z`（步进 `keyboard_body_z_step=0.004 m`） | **△ `buttons[2]` / ✕ `buttons[0]`** |
| R2 连续压低（仅 `axes[5] < 0`，增益 `joy_height_axis5_scale=0.5`） | `axes[5]` |

高度增量限制：`body_z_max=+0.015 m`、`body_z_min=-0.08 m`（相对 `nominal_height=0.2 m`）。键盘 **`t` / `b`** 与手柄高度通道语义一致，在同一 `champ_teleop` 进程内生效。
