# 部署与开机自启（systemd）

整机自启由工作空间根目录的 **`main.sh`** 托管：systemd 只负责在开机时调用
`./main.sh start`、关机/停服务时调用 `./main.sh stop`，其余逻辑（ROS 环境、
CAN/手柄/灯带参数、PID/日志、自检）与手动操作完全一致。

## 1) 改代码后：编译 + systemd 重启

`systemctl restart` 会重新执行单元里的 `main.sh start`（等价于 `./main.sh restart`），
**前提是已把新代码编进 `install/`**。主栈包可只编到 `trotbot` 相关，避免工作区里
**minidog**（需 catkin）、**champ_gazebo**（需 Gazebo 依赖）等包导致全量 `colcon build` 失败：

```bash
cd ~/trotbot_ws
source /opt/ros/humble/setup.bash
colcon build --symlink-install --allow-overriding champ champ_msgs --packages-up-to trotbot trotbot_status_led trotbot_can_bridge trotbot_dynamics
sudo systemctl restart trotbot-basic
sudo systemctl status trotbot-basic --no-pager
# 可选：看日志
# journalctl -u trotbot-basic -b -e --no-pager
```

- 服务名以 `/etc/systemd/system/` 下实际 **`.service` 文件名** 为准（本仓库示例为 **`trotbot-basic`**）。若曾修改过 unit 文件，需先 **`sudo systemctl daemon-reload`** 再 **`restart`**。
- 仅手跑 launch、**未**用 systemd 时，没有可 `restart` 的 unit，请用 `./main.sh restart`。

## 2) 开机自启（systemd，由 main.sh 托管）

单元模板：[`src/trotbot/config/systemd/trotbot-basic.service.example`](../../src/trotbot/config/systemd/trotbot-basic.service.example)
（已按本机 `cat` / `/home/cat/trotbot_ws` 填好；换机器/用户时改 `User`、`WorkingDirectory`、`PIDFile` 与 `ExecStart/ExecStop` 路径）。

安装并立即启用：

```bash
sudo cp /home/cat/trotbot_ws/src/trotbot/config/systemd/trotbot-basic.service.example \
        /etc/systemd/system/trotbot-basic.service
sudo systemctl daemon-reload
sudo systemctl enable --now trotbot-basic.service
systemctl status trotbot-basic.service --no-pager
journalctl -u trotbot-basic.service -b -f      # 跟随日志
```

单元要点：

| 配置 | 作用 |
|------|------|
| `Type=forking` + `PIDFile=…/log/trotbot_ctl/stack.pid` | 复用 `main.sh start` 的后台启动与 PID 文件 |
| `ExecStart=/home/cat/trotbot_ws/main.sh start` | 真机参数：CAN + 手柄 + 灯带，无 RViz/xterm |
| `ExecStop=/home/cat/trotbot_ws/main.sh stop` | 与手动停止一致（SIGINT 优雅退出） |
| `After/Wants=can-up.service` | 等 `can0/can1` 拉到 1Mbps 后再起栈（该服务已 enable） |
| `TROTBOT_HEALTH_STRICT=0` | 开机时电机可能还没上电，自检失败也保留进程，避免 systemd 反复杀栈重启 |
| `Restart=on-failure` | 主进程异常退出时自动拉起 |

**权限**（本机 `cat` 已全部满足，无需 sudo）：

- 灯带：`spidev` 后端，用户需在 **`dialout`** 组；
- 手柄：用户需在 **`input`** 组；
- 无图形环境，单元不启动 RViz/xterm，键盘遥控不可用，请用手柄。

**不要与手动命令混用**：服务已启用时，要手动调试请先
`sudo systemctl stop trotbot-basic`，再用 `./main.sh start|stop`；调试完
`sudo systemctl start trotbot-basic` 交回 systemd。

关闭/卸载自启：

```bash
sudo systemctl disable --now trotbot-basic.service
# 彻底移除单元文件
sudo rm -f /etc/systemd/system/trotbot-basic.service && sudo systemctl daemon-reload
```

## 3) `restart_trotbot_basic.sh`（已废弃，兼容保留）

脚本仍在原路径并可执行，但只是转发到 `trotbot_ctl.sh restart`（改为后台运行、带 PID/日志）。新操作请统一用 `./main.sh restart`。若由 **systemd** 管理整机启动，请优先用本文第 1 节，不要在机器上双起第二套 launch。
